Verified 2026-10-16 against the current official OpenAI documentation:

- [Models](https://developers.openai.com/api/docs/models): `gpt-6-luna` and `gpt-6.1-sol` support Responses and web search. The existing research configuration selects `gpt-6-luna`; ordinary inference and one-shot smoke configurations are unchanged.
- [Web search guide](https://developers.openai.com/api/docs/guides/tools-web-search): the Responses `web_search` tool accepts `external_web_access` and `search_context_size`. A `web_search_call` records the action and optional consulted sources; output text may carry `url_citation` annotations. These are structural source records, not verification of a claim.
- [Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create): `store=false`, `max_output_tokens`, `max_tool_calls`, `truncation="disabled"`, and `include=["web_search_call.action.sources"]` are supported. Responses expose status, output, optional usage token counts, and error fields. The adapter rejects unsupported shapes; it does not fall back to a different model, tool or schema.

## Implemented boundary

`public-research-v1` is a separate, default-disabled request and result contract. A request contains only an operation ID, one bounded public question, and an opaque random grant handle. It has no fields for private motivation, history, participant identity, credentials, URLs, tools, project, or control objects. The question contract rejects normalized scheme, scheme-relative, bare-domain and path-like URL forms, plus percent and HTML encoding markers at any nesting depth. The worker constructs the brief with the existing screening pipeline and fixes the model, web-search tool, project, storage, output token limit, one search call, one provider attempt and timeout. The SDK adapter is inside the trusted worker; its production constructor uses the protected credential file and fixed OpenAI endpoint. Normal tests inject a fake SDK client and block external network and credential loading.

The only issuer in this change is `install_synthetic_authorization`, a trusted local bootstrap method used by offline tests. It installs an exact brief digest, operation ID, peer UID, complete provider configuration, a validity window of at most ten minutes, and one execution allowance. No IPC or ordinary chat operation installs or renews a grant. Screening establishes a bounded shape; it does not approve disclosure. Production authorization and private-topic abstraction are unavailable. Therefore this change does not enable production paid research.

The worker checks the peer UID and exact handle, question, operation, digest, configuration, validity and stop/spend state. It atomically reserves the operation in `ProviderStateStore` before contacting the provider, then converts each terminal reservation into a durable outcome record with response ID and token usage when safe and available. Structurally valid usage survives a malformed output body; a recordable response ID is screened for known private canaries before persistence, including parser rejection paths. Failure to persist that record latches the worker closed. The operation ID is the durable one-use key: concurrent duplicates, restarts, timeouts and lost responses cannot renew it. Revocation consumes the same key and marks the in-memory grant revoked. If the worker restarts, no grant is re-created automatically; an independently trusted synthetic bootstrap would have to install one, and the existing reservation or outcome record still denies a consumed operation. An unrecorded or uncertain provider attempt is never retried. This preserves the uncertainty of a possibly transmitted request.

Provider output is bounded and parsed through the existing provenance parser. Unsupported URLs, malformed annotations and invented source metadata fail closed. The Russian output gate runs before a bounded result is returned. Results include explicit outcome, provider usage when available, source records, and an uncertainty statement. The adapter reuses the existing classifier to distinguish transient rate limits, billing quota, ambiguous quota, and confirmed spend limits; only a confirmed spend-limit code durably suspends further attempts. `claim_status=unverified` and `semantic_support=not_evaluated` remain distinct from structural metadata validation. Results do not alter beliefs, memory, missions, consent, publication or participant state.
