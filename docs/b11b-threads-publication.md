## Evidence through dispatch and restart

The INT24 journal hands the immutable content and publication type to the existing outbox. A reply's parent is the verified inbound event ID, never model-selected text. Independent approval binds that exact draft, source, account, mission and parent. Existing Stop, privacy, mission, spend and expiry checks remain in force immediately before effects.

The service reserves the durable operation, records `SENDING`, checks `/me` before each POST, records the returned container ID, and publishes that container once. It commits `provider_publication_id` with `publication_id_received_verification_pending` before readback. The minimal sufficient successful evidence is:

| Type | Readback and required binding |
| --- | --- |
| Top-level post, unchanged | `GET /{returned_id}?fields=id,owner,replied_to`: exact returned `id`, `owner.id` equal to configured app-scoped user ID, no parent. A malformed present parent fails. |
| Reply | Fresh `GET /me?fields=id` equal to configured user ID, then `GET /{returned_id}?fields=id,is_reply_owned_by_me,replied_to`: exact returned `id`, literal Boolean `true` ownership, and `replied_to.id` equal to the approved parent. No `owner` or username fallback. |

The returned publication ID ties readback to the original publish request; its `creation_id` ties it to the approved text/parent container. There is no content search or need to infer identity from matching text. All calls retain the fixed TLS host/version, Bearer header, redirect rejection, deadline and response bounds. Reply verification adds one bounded account GET; it does not page or retry.

A failed account read **after** publishing, timeout, missing/wrong/malformed ownership or parent, wrong publication ID, or interrupted readback cannot prove no effect. It retains the original IDs and `UNKNOWN`, which pauses further publication. On restart, `recover-sending` moves a possible write to `UNKNOWN`. Reconciliation uses only the stored original publication ID and the same type-specific evidence; it creates no container and makes no POST. Failed reconciliation stays unresolved. An interrupted reconciliation claim needs its existing purpose-bound recovery approval before another reconciliation attempt. No schema, operation identity, evidence migration or cursor reset is needed: older `UNKNOWN`/`SENDING` operations with a recorded publication ID use this same read path; older confirmed operations are untouched.

Without a returned publication ID (lost publish response, for example), the contract supplies no operation key proving which publication resulted or that none exists. The container ID/status or a text/time match is insufficient account/publication/parent evidence. Keep the account paused. A later separately authorized investigation would need authoritative linkage between that **original container/publish operation** and its actual publication ID before this runtime could verify it. This PR adds no discovery fallback, manual ID injection or resend procedure.

Offline evidence: `tests/test_b11b_publication.py` checks exact request sequences and persisted outcomes through both the service and connected INT24 worker/runtime fixtures, including post/reply success, malformed and wrong ownership/parent/ID evidence, read/account failures, missing publication ID and restart reconciliation without POST. The existing interrupted-verification test now covers replies too. PR80's polling/cursor tests remain in the full gate.

   ```sh
   python -m app.ops.int24_threads_runtime draft OPERATION --activate-live --config /absolute/existing/operator.json
   python -m app.ops.int24_threads_runtime approve OPERATION --expires-minutes 5 --activate-live --config /absolute/existing/operator.json

   python -m app.ops.int24_threads_runtime draft OPERATION --activate-live --config /absolute/existing/operator.json
   ```

   Expected effect per dispatched draft: one text container and one published top-level post **or** reply to the reviewed parent, followed by the evidence checks above. Require persisted `CONFIRMED`, the same IDs/parent and `provider_publication_details_verified`; do not treat a returned publish ID alone as verification. 5. For failure or lost command output, inspect `draft OPERATION` and its existing durable audit before doing anything else. If `SENDING` remains after the original worker has stopped, run `recover-sending OPERATION`, then inspect again. With `UNKNOWN` and a stored publication ID, run `reconcile OPERATION` using the same flags/config; inspect `draft` again. This performs GETs only and can yield `verified_success` or remain unresolved. If an earlier reconciliation claim was interrupted, use `approve-reconciliation-recovery OPERATION --expires-minutes 5`, then `recover-reconciliation OPERATION APPROVAL_REFERENCE` with the same flags, before another reconciliation. This clears only the interrupted claim. Without a publication ID or sufficient evidence, retain the pause and investigate the original operation. Never redispatch, create a replacement/wakeup, reset stores, or change the ID to obtain a clearer result.

Publication effects and model costs are separate. `draft`, `approve`, `dispatch`, reconciliation and recovery invoke no model. New `wakeup` / `process` work may incur existing public-worker model charges, and any already enabled research path has its own authorized requests/costs; review the configured budget and backlog first. Neither draft generation nor an INT27 receipt authorizes publication. No token grant, live readback, upload timing, semantic safety, autonomous readiness or deployment is established by offline success.

For the first top-level post on an empty profile, follow the [ordinary startup sequence](int24-threads-runtime.md#ordinary-startup-with-an-empty-profile). A reply root is optional for top-level publication and mention-only checks; configure it only after confirmed ownership readback.
