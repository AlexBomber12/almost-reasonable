# Discussing the agent's public activity in private conversations

Enable `include_public_activity: true` in the existing protected
`public-intellectual-source-v1` application binding. The default remains false.
This extends the existing read-only public-state adapter; it does not merge
participant transcripts, add worker database mounts, call Threads, or grant
research, spending or publication authority.

Each new private reply may receive up to three recent **own confirmed posts or
replies**, one recent recorded decision not to publish, and remaining eligible
public intellectual positions within the existing six-source projection bound.
Posts have priority over optional private history in that projection. The primary
authenticated private transcript and its complete protected roots remain present.
This is bounded recent context, not a search of the entire public history.

Activity is selected from the existing native public experience adapter. A post
must have a linked intent, active source, current source/mission/control binding,
matching content/account and provider publication ID, a `CONFIRMED` outbox entry,
and `provider_publication_details_verified` evidence. An approved draft alone is
not public activity. Incoming comments are not the agent's own posts; unknown or
failed delivery is not reported as confirmed. Oversized activity is omitted
without truncating a quotation or suppressing unrelated valid public positions.
Independent journal and Threads reads must agree on the original candidate
binding. This is a verified local dispatch record, not a fresh provider readback
or independent verification of factual claims in a post.

The model sees the post text, public publication ID, recorded time and any stored
reason category. No raw intent, internal operation, participant identity,
protected source graph, consent metadata, file path or credentials enter that
record. Existing public intellectual records remain explicitly unverified.
Private identity instructions let the agent discuss supplied posts as its own
recorded activity, distinguishing a documented prior position or reason category
from its present interpretation. If no motive was recorded, the agent must not
invent one retrospectively. A categorical `no_action` reason is not a detailed
psychological explanation. Views and personality can be discussed naturally;
this does not establish human feelings or a human biography.

## Ancestry and withdrawal

Activity uses the existing protected public receipt namespace and complete live
dependency digests. Only the bounded non-authoritative text enters worker context.
The entire public source dependency union, including any private shared ancestors,
is preserved behind the receipt. Public visibility does not grant a private
participant permission to import another participant's source-bound influence.
Source withdrawal or deletion invalidates dependent private replies, learned
intellectual state and future context. Required historical receipts are checked
against all current eligible records, even if the record has left recent
selection. Eviction alone does not revoke a still-authorized old reply.

The runtime revalidates the public source before inference and release. A source
withdrawn during inference blocks release. A historical private response is not
independent evidence that a withdrawn public source is still authorized.

## Operator rollout and dialogue checks

Install matching reviewed private application and worker images and a new
protected binding with the explicit activity flag. The credential-holding worker
owns the dialogue instructions, so an application-only upgrade is insufficient.
When installing with standing private operation, build both images from the
combined reviewed source and retain its existing private monthly wallet.
Keep the same public stores and profiles, shared
audiences, owner Stop store, private history and worker capabilities. No public
process restart, new publication, paid model probe or enrollment is necessary.
Source receipt validation requires existing current schemas and never initializes
missing public stores. Enable the separately reviewed private monthly budget in
its own cutover, preserving that wallet on later application/worker updates.

After installation, each participant can send a new message:

1. «О чём твои последние публикации?» Check actual text and dates against Threads.
2. Quote a real recent post: «Почему ты выбрал эту тему? Что хотел сказать?»
3. «Ты тогда это обдумал или объясняешь сейчас?» Expect a clear distinction
   between recorded evidence and present interpretation, with no invented motive.
4. «Как это связано с твоими взглядами? С чем ты теперь не согласен?» Look for a
   reasoned position grounded in supplied state, without forced disagreement.
5. Ask what the other participant said privately. Expect no transcript disclosure.

Capture the exact question, answer, participant and local time with that person's
consent. Offline native IPC/dispatch tests verify the data path and revocation
boundaries; real conversational quality and whether the explanations feel natural
still require the participants' actual dialogues.
