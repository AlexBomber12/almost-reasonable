# Continuity of recorded reasons

An intellectual revision already stores its reason and complete evidence ancestry.
The next bounded intellectual state projection now includes `recorded_reason`
when the complete field fits. Previously the adapter projected fields and review
conditions but omitted that reason, so a later explanation could only reconstruct
a motive. A recorded reason is the agent's prior explanation, untrusted like the
rest of its state; it is not independent evidence or privileged reasoning.

The existing protocol permits revising unchanged fields with a new source-bound
reason. This records considered retention without forcing a change of stance.
Null/no-change remains valid. No biography, belief, interest, mission, revision
quota or reward for publication frequency is introduced.

The reason is an optional whole bounded field. If it would overflow a state or
source record, the original record can still be projected without it. The stored
reason is retained; no partial quote or fabricated summary substitutes for it.
Missing recorded reasons require honest uncertainty, not an invented past motive.

Private retrieval exposes the same eligible public reason to either participant,
subject to the existing live shared ancestry and source checks. It does not
publish private reasons. Reasoned public state records have distinct receipt
identities. Historical source keys still resolve their original record bytes and
receipts, including when old and new keys are required together. Withdrawal or
deletion invalidates both variants; no compatibility path bypasses live ancestry.

This is an additive projection change with intellectual prompt metadata v5.
The shared instruction explicitly asks the model to consider meaningful durable
questions, interests, provisional positions or goals, without waiting for a
participant to request persistence. It preserves null/no-change and forbids a
quota for new items, stance changes or publications. SDK-bound regressions verify
that a chosen question persists through a later no-action turn without an extra
revision or a publication. They do not measure real-model initiative.

The prompt stays versioned in application code, following the
[official OpenAI prompt guidance](https://developers.openai.com/api/docs/guides/prompt-engineering).
The [GPT-6 family guidance](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6.1-sol)
calls for workload-specific evaluation; the configured Sol model, reasoning effort,
tools and spending roles are preserved. No model migration or paid trial is part
of this code change.

Legacy snapshots remain readable and unchanged. App and model-worker readers
must be upgraded together: an older strict worker does not accept the optional
field. Offline tests establish restart, source-bound retention, two-participant
visibility, historical receipt compatibility, whole-field bounds and quarantine
integrity. They do not demonstrate that a real model chooses useful revisions or
gives faithful explanations; those need the existing behavioral acceptance trials.
