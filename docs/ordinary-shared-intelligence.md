# Ordinary shared intellectual influence (PR3)

The same agent can develop a source-bound abstract position in one private
conversation and use it in another authorized conversation or public decision.
Private relationship memory and fictional autobiography remain principal scoped.
Nothing seeds a substantive belief, mission, research question or interest.

## Admission and limits

`SharedIntelligence(..., ordinary_abstractions_enabled=True)` enables an explicit
`abstract_to_shared` policy, separate from the existing exact-consent local review
path. `transition` accepts only the existing four abstract intellectual record
types. Audience comes from trusted application configuration. The private CLI
requires both `--enable-ordinary-abstractions` and `--enable-shared-proposals`;
the worker's separate finite shared-proposal permission remains required. A model
suggestion grants no tool, expenditure, research or publication authority.

The ordinary path does not ask the participant to approve each safe transition.
The versioned Russian enrollment notice already explains shared influence,
possible source inference with two participants, operational access, external
processors and the separate consent needed for identifiable disclosure.

The new H screen combines identifier, quotation, protected-marker and source
overlap checks with a conservative general-concept vocabulary and whole-record
size bound. It admits combinations rather than a list of approved opinions.
Unknown wording is uncertain and cannot be automatically promoted. This means
many otherwise safe formulations will be withheld. The screen is not a semantic
safety or anonymity proof; the richer existing reviewed path still requires
exact source consent. Changing the screen's vocabulary is a policy revision,
not model-controlled permission. Real-model usefulness and privacy acceptance
remain PR9 work.

The protected manifest binds the policy and screen version, exact candidate,
initiating identity, audiences, revision and complete source union. Readers and
backup validation recheck active ordinary values against the current screen.
An ordinary revision cannot widen a reviewed candidate's authority.

## One position, separate private context

The shared proposal worker sees only the current participant input and a bounded
eligible abstract position through an opaque handle. It can revise a position
initiated by another participant when the existing audience permits both the
current participant and all proposed recipients. Protected provenance inherits
every source and reviewed input. Another participant's raw input is used only
inside application privacy comparisons and is never sent to that worker.

Both private conversations consume the same durable shared revision history;
private state and fiction stay separately labeled. New positions that cannot
retain the complete context dependency graph are withheld. Source deletion,
revocation and old-backup reconciliation retain their existing protected graph
boundaries and invalidate dependent items and responses. No originating
principal, event identity, consent, manifest or source-specific rationale appears
in another participant's model projection.

## Narrative integration

The shared wrapper preserves the narrative protocol, fictional classification,
non-evidence flags and full serialized byte limit. Worker configuration, finite
pilot permission and application permission all still gate narrative context.
Combined context uses the narrative provider instructions.

The existing protected creator-reply and narrative-context edges bind a generated
episode to the creator reply's shared authorization. Later use walks those
ancestors, requires authenticated completed server release and live creator
authorization, and inherits the shared operation/source budget. Output persistence
rejects a reply that omits required shared authorization. Shared invalidation
erases the generated episode, descendant episodes, associated receipts and
dependent reply/state payloads while preserving unrelated private fiction.

## Public consumer

`SharedIntellectualSource(shared, account)` is a trusted application capability
bound to one public account and the explicit `public:<account>` audience. Supply
it to `ThreadsRuntime(shared_intellectual_source=...)`. This does not invent an
authenticated private participant for a public account. It reads only ordinary
abstract records whose audience permits that account and rechecks the private
privacy gate at every use. The credential-holding public worker gets only the
bounded abstract projection, never private database access.
The existing private and public privacy ledgers remain independent. Configuration
that aliases their files is rejected before startup, since nested write fences
on the same SQLite file would block the public persistence boundary.

Public sources are labeled `shared_abstract_influence`, unverified and explicitly
not independent public evidence. They can inform intellectual development;
they cannot establish a factual public claim. The public journal binds admitted
source identities and controls, so withdrawal blocks later dependent inference,
state use and publication approval. Actual deployment wiring remains explicit;
this change does not mount a private store into a public worker or enable live
production behavior.

CI now runs on pull requests targeting dependent branches as well as `main`.
This preserves the full gate and exact-head artifact evidence for a stack of
unmerged stages. Each stage still needs current-head CI and Codex Review before
human merge authorization.
