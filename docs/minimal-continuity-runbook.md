# Запуск отдельного continuity lab

Протокол и критерии: [minimal-continuity-experiment.md](minimal-continuity-experiment.md).
Исходный протокол зафиксирован коммитом `9116259` до реализации. Этот runbook
описывает реализацию и ограничения, не изменяет критерии успеха.

Это локальный операторский CLI, а не второй production web-чат. `a` и `b` — области
данных, не логины и не механизм аутентификации. Передавать CLI двум людям с общим
доступом к файловой системе как защищённый многопользовательский сервис нельзя.
Разговоры пока ведёт оператор, явно выбирая участника. Приватный web-интерфейс
существующего приложения не меняется. Ни один production entrypoint не импортирует
эксперимент автоматически.

## Offline проверка установки

Из checkout с установленными `requirements-dev.txt`, создайте **новую**, ранее не
существовавшую директорию вне рабочих данных (пример для Linux):

```sh
python -m app.continuity_cli create /tmp/ar-lab-example
python -m app.continuity_cli event /tmp/ar-lab-example post public post \
  'Синтетический пост: уверенность не заменяет оснований.' --source operator:synthetic
python -m app.continuity_cli event /tmp/ar-lab-example question a message \
  'Что ты публиковал и почему?'
python -m app.continuity_cli context /tmp/ar-lab-example question
```

`create` не принимает существующую директорию; `Lab` проверяет application ID,
версию и inode файлов. Symlink/hardlink базы не принимаются. Сырой опыт не удаляется:
компактация — ограниченная рабочая проекция с явным счётчиком пропусков.
К каждому виду публичного опыта отведено до двух записей; недавних событий до
четырёх; решений до трёх. До 24 активных записей памяти с текущей и предыдущей
ревизией и исходными событиями; 32 KiB на кадр. Переполнение явно блокирует inference,
не выбрасывает важную позицию молча. Это ограничение прототипа тоже оценивается.

Для проверки механики можно дать **заранее записанный синтетический** ответ в
UTF-8 JSON-файле вне Git:

```json
{
  "action": "reply",
  "text": "В загруженном примере есть пост об основаниях уверенности. Причина его публикации не записана.",
  "reason": "Различаю содержание примера и неизвестный мотив.",
  "based_on": ["post", "question"],
  "question_key": null,
  "updates": []
}
```

```sh
python -m app.continuity_cli step /tmp/ar-lab-example turn-1 question --response /tmp/recorded-response.json
python -m app.continuity_cli inspect /tmp/ar-lab-example a
```

Результат помечен `model_kind=recorded`, `effect=shadow_only`, приёмка NOT_RUN.
Этот пример ничего не доказывает о качестве Sol. Содержимое ответов не захардкожено
в ядре. Новая база пуста: никакой биографии, интересов или миссии в seed нет.

## Реальный ограниченный эксперимент: пока не запущен

Платный запуск выполняется отдельным согласованным шагом после PR/review.
Не используйте production контейнер для загрузки экспериментального кода.
Нужен отдельный процесс/контейнер с новой директорией данных; без монтирования
частных историй, рабочих SQLite, owner credentials и Threads token. Подключаются
только существующий защищённый ключ, общий budget broker route и Stop.
OS peer для route должен быть отдельно проверен; при отказе брокера обхода нет.

Защищённая конфигурация активации (каталог 0700, файл 0400, собственник процесса):

```json
{
  "version": "ar-continuity-lab-v1",
  "experiment_root": "/absolute/new/experiment-directory",
  "project_id": "proj_REPLACE_WITH_EXISTING_MAIN_PROJECT",
  "organization_id": "org-REPLACE_WITH_EXISTING_ORGANIZATION",
  "budget_route": "/absolute/protected/existing-private-sol-route.json",
  "stop_path": "/absolute/protected/existing-emergency-stop.json",
  "max_calls": 24
}
```

Значения здесь — placeholders, не рабочая активация. Ключ хранится только в
существующем `/run/secrets/openai-api-key` с защитой trusted factory. Новый ключ,
API-проект, кошелёк и повышенный бюджет не создаются. `RemoteBudget` проверяет
project/lane; snapshot требует действующий общий лимит $40. Перед каждым SDK-вызовом
`BudgetedResponses` резервирует стоимость в существующем кошельке и учитывает
usage; при непонятном исходе удержание сохраняется. API invoice этим не подменяется.

```sh
python -m app.continuity_cli step /absolute/new/experiment-directory turn-1 question \
  --live-config /absolute/protected/lab-activation.json --allow-paid
```

Sol `gpt-6.1-sol`, один Responses request, tools=[], store=false, retries=0,
timeout=25, max_output_tokens=2048, reasoning=low. Нет прямого поиска/публикации;
исследовательские материалы оператор добавляет событием `research` с `--parent`
на реальное теневое намерение `research`. Это проверяет перенос опыта, не качество
автономного получения данных или работу Meta. Эти части полного MVP остаются вне
эксперимента.

Выходная схема задаёт до 2048 символов для ответа и до 200 для кратких оснований
и полей памяти. Проверка приёмника отдельно сохраняет UTF-8 границы: до 8192 байт
для ответа и до 800 для короткого поля. Сериализованный ответ ограничен 32 KiB.
Это предотвращает отбрасывание корректного русского ответа из-за смешения символов
и байтов; токенный предел, число вызовов и денежный лимит остаются прежними.

`max_calls` ограничивает сохранённые live admissions всей базы (включая неудачи),
перезапуск процесса его не сбрасывает; допустимы 1–60. Это дополнительная граница
эксперимента, не замена общего денежного лимита. Изменение активации — операторское
решение, не команда из диалога. SDK import/client сам по себе не тратит деньги.

## Неудачи и наблюдение

- Повтор того же operation ID возвращает сохранённый результат без inference;
  другой вход с тем же ID отклоняется. Осмысленная новая попытка имеет новый ID.
- SQLite mutex удерживается во время шага; конкурентное изменение/recovery
  получает `busy`. При смерти процесса mutex освобождается, durable admission
  остаётся. `recover ROOT` или следующий шаг помечает его `unknown`; повтор на том
  же ID не запускает модель. Это не утверждение об отсутствии списания у провайдера.
- incomplete/refusal/timeout/invalid output/budget/Stop — терминальная ошибка,
  не no_action. Неудачный ответ не применяет предложенную память. Ошибки SDK
  санитизированы; сырые исключения/ключи не экспортируются.
- Журнал содержит точный кадр решения, итог, краткое заявленное основание, ссылки,
  ревизии и длительности. Он не доказывает субъективные мотивы модели. Личные
  кадры остаются в отдельной базе; `inspect SCOPE` ограничивает показ областью.
- Timing `context` включает admission и подготовку, `model` — вызов, `total` —
  обработку до финальной записи метрик. Для p95 пользовательского ожидания отдельно
  измеряется полное внешнее время CLI, включая финальную запись и вывод.

Для каждой версии/последовательности сохраняются все ID шагов, выходы, ошибки,
wall time и оценки обоих людей 0/1/2 с объяснением. Не выбирайте только лучшие
разговоры. Перезапуск/компактация — открытие той же базы и добавление шума, не
создание новой истории. Для независимой последовательности нужна новая база;
лимит общего кошелька при этом всё равно сохраняется.

До фактического выполнения E01–E06 и независимой оценки обоими участниками
`inspect` сохраняет консервативный статус NOT_RUN: автоматического принятия по
числу вызовов нет. Ручной итог оформляется по замороженному протоколу вне Git.
Любая последующая web-оболочка, автоматический поиск, перенос частных обобщений,
production deploy или реальная публикация потребуют отдельной реализации/проверки.
