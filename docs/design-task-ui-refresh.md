# Задача: обновление интерфейса private web и owner control

Макет: `docs/design/Almost Reasonable Prototype.dc.html` (кликабельный, светлая и тёмная тема).
Ревью с обоснованием: `docs/design/Design Review.dc.html`.
Прототип — эталон вида и поведения. Код из него не переносить: в нём inline-стили, а CSP приложения (`style-src 'self'`) их запрещает.

## Общие правила

- Все стили — только в `app/private_web/chat.css` (и `owner.css`). Никаких `style=""` и `<style>` в HTML: CSP их заблокирует.
- Все HTML-страницы (чат, вход, приватность, сообщение, ошибки) подключают `/assets/chat.css` и `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`, `lang="ru"`.
- Пользователь не должен видеть: `consent_id`, `operation_id`, `content_reference`, версию уведомления, ISO-даты, JSON, английский текст.
- `alert()` / `confirm()` не использовать. Вместо них — тост (`role="status"`) и модальный диалог (`role="dialog"`, `aria-modal`, фокус внутри, Esc закрывает).
- Минимальный размер зоны нажатия — 44×44 px.
- Шрифт остаётся `system-ui`.
- Знак ✳ заменить монограммой «AR»: скруглённый квадрат, фон `--mark`, белый текст.

## 1. Вход — `wsgi.py: _login_page, _login`

- Шапка карточки: монограмма + «Almost Reasonable». Заголовок «Вход». Строку «Личный разговор» и подзаголовок удалить.
- Неверный пароль (401) и блокировка (429) отдают ту же страницу входа: имя пользователя сохранено, пароль очищен, сверху блок ошибки (`role="alert"`):
  - 401 → «Неверное имя или пароль»
  - 429 → «Слишком много попыток. Попробуйте через N минут.» (N из `lockout_seconds`)
  - 403 CSRF → «Сессия входа устарела. Попробуйте ещё раз.»
- У поля пароля — кнопка «Показать / Скрыть».
- Пока отправляется форма, кнопка показывает «Входим…» и неактивна.
- Коды статусов и `Retry-After` не менять.

## 2. Страницы ошибок — `wsgi.py: _error` (не для API)

Единый русский шаблон в стиле приложения: мелкая строка «Ошибка 404», заголовок, одна фраза, кнопка «Вернуться в чат» (`/chat`).

| Статус | Заголовок | Текст |
|---|---|---|
| 400 | Не удалось выполнить запрос | Обновите страницу и попробуйте снова. |
| 403 | Нет доступа | Войдите снова или вернитесь в чат. |
| 404 | Страница не найдена | Возможно, ссылка устарела. |
| 405/413/415 | Запрос не поддерживается | Вернитесь в чат и попробуйте снова. |
| 503 | Сервис временно недоступен | Попробуйте через несколько минут. |
| 500 | Что-то пошло не так | Попробуйте ещё раз чуть позже. |

API-ответы (`/api/*`) остаются JSON без изменений.

## 3. Онбординг — новый вид `/privacy`, пока уведомление не подтверждено

Сейчас `/chat` до подтверждения редиректит на полную страницу `/privacy`. Вместо этого, пока уведомление не подтверждено, `/privacy` показывает онбординг:
- монограмма, заголовок «Прежде чем начать»;
- 3 нумерованных пункта (текст — как в прототипе): «Где обрабатываются данные», «Ваши слова не публикуются», «Можно удалить»;
- ссылка «Полный текст уведомления» раскрывает `NOTICE_RU` абзацами (`<details>` или отдельный вид). `<pre>` не использовать;
- основная кнопка внизу «Понятно, к разговору» → `POST /api/privacy/notice` → при успехе `location.assign('/chat')`, при ошибке — блок ошибки над кнопкой.
- Никаких списков, «Выйти» и прочих разделов на этом экране.

Тексты пунктов нужно согласовать с владельцем: это сокращение юридического текста, полный `NOTICE_RU` остаётся доступен по ссылке.

## 4. Чат — `wsgi.py: _chat_page`, `chat.js`, `chat.css`

Удалить:
- видимый `<h1>Разговор</h1>` (оставить с классом `visually-hidden`);
- подпись «Личный разговор» в шапке;
- подписи «Вы» / «Собеседник» у сообщений (`message__speaker`). Для скринридеров — `visually-hidden` текст «Вы:» / «Almost Reasonable:»;
- ссылку «Управление источником» под сообщениями (в HTML и в `showHistory`);
- зелёную полосу слева у ответа агента: ответ — обычный текст без фона;
- `resize: vertical` у поля ввода;
- постоянную подсказку «Enter — отправить…»: она показывается только в пустом состоянии.

Шапка: монограмма + «Almost Reasonable» слева, кнопка «⋯» (`aria-label="Меню"`, `aria-expanded`) справа. Меню: «Приватность», «Тёмная тема / Светлая тема», разделитель, «Выйти». Закрывается по клику вне меню и по Esc.

Лента:
- разделители дат «Сегодня» / «Вчера» / «12 октября» по `occurred_at` (сервер отдаёт его в `/api/history`; в SSR-рендер `_chat_page` тоже добавить);
- сообщение пользователя справа, фон `--bubble`, максимум 82% ширины; ответ агента слева, текст 16px / 1.6;
- пустое состояние — без карточки, по центру: «С чего начнём?», «Напишите что угодно — разговор виден только вам.», подсказка про Enter.

Индикатор ответа: пока идёт `POST /api/messages`, сообщение пользователя сразу добавляется в ленту, под ним — строка «Печатает» с тремя анимированными точками (уважать `prefers-reduced-motion`). После ответа — `refreshHistory()`.

Поле ввода:
- авто-рост до ~160px (`field-sizing: content` + JS-фолбэк по `scrollHeight`);
- кнопка отправки — круглая 40px, стрелка «↑», `aria-label="Отправить"`; без текста неактивна;
- под полем одна строка: «ИИ-агент. Истории от первого лица могут быть вымыслом.» (это `NARRATIVE_DISCLOSURE_RU` в короткой формулировке; `data-version` сохранить на этом элементе). Блок дисклеймера над лентой удалить;
- пока проверяется сеанс, плейсхолдер — «Подключаемся…».

Статусы — переписать тексты в `chat.js`:

| Ситуация | Было | Стало |
|---|---|---|
| Сбой сети / 5xx | «Не удалось отправить. Результат неизвестен. Повторите отправку явно.» | Блок ошибки «Не удалось отправить» + кнопки «Отменить» и «Повторить» в одну строку |
| Восстановлен pending | «Результат прежней отправки неизвестен. Повторите её явно с тем же номером сообщения.» | Тот же блок: «Сообщение могло не отправиться» + «Отменить» / «Повторить» |
| 400/413/422 | «Сообщение не принято…» | «Сообщение не принято. Измените текст и попробуйте снова.» |
| Ответ остановлен | «Ответ остановлен. Ваше сообщение сохранено.» | «Ответ сейчас недоступен. Сообщение сохранено.» |
| pending | «Сообщение сохранено. Ответ ожидается.» | «Ответ придёт чуть позже» |
| Черновик восстановлен | «Черновик восстановлен.» | без изменений, исчезает через 3 с |
| Сессия истекла | как есть | «Сеанс завершён» + ссылка «Войти» |

Логику идемпотентности (`pendingMessage`, тот же `message_id` при повторе) не менять: «Повторить» = текущий «Повторить отправку», «Отменить» = текущий «Отменить повтор». Отдельную кнопку `#discard-pending` под формой удалить, её функция переходит в блок ошибки.

## 5. Приватность (уведомление подтверждено) — `privacy.py: page()`

Шапка: «←» (на `/chat`) + «Приватность». Внизу «Выйти» не нужен: выход есть в меню чата.

Секции сверху вниз:
1. **Уведомление о данных** — строка-карточка «Подтверждено 25 октября» → полный текст. Кнопку «Подтвердить уведомление» здесь не показывать.
2. **Мои сообщения** (вместо «Мои источники») — список: первая строка текста (обрезать с многоточием), дата; клик → экран сообщения. Под списком: «Откройте сообщение, чтобы разрешить цитату или удалить его.» Пустой список → «Пока нет». В `_source_ids` вернуть также `content` и `occurred_at`. Пагинация — «Показать ещё».
3. **Разрешения на публикацию** — карточки: превью цитаты «…», «Дословно · до 26 окт.», бейдж статуса. Статусы: «Действует» (ok) + кнопка «Отозвать», «Отозвано», «Истекло», «Заблокировано удалением» (нейтральные). Для превью сделать join на `private_payloads` по `content_reference`. Пустой список → «Пока нет».
4. **Удаления** — показывать, только если есть записи. «Сообщение от 2 окт.» + бейдж: «Удалено» (applied), «Ожидает» (pending), «Не завершено» (incomplete_blocked) + кнопка «Повторить» (вызывает `/api/privacy/reconcile`). Отдельный блок «Повторить локальное удаление / Проверить незавершённые операции» удалить.

Удалить с этой страницы: дубль `NARRATIVE_DISCLOSURE_RU`, строку «Отдельное согласие необязательно…», «Версия …: …».

Результаты операций — тостом: «Разрешение отозвано», «Удаление завершено», «Не удалось выполнить. Попробуйте ещё раз.» Перезагрузка страницы допустима, но тост должен её пережить (через `sessionStorage` или query-флаг).

## 6. Экран сообщения — `privacy.py: source_page()` (`/privacy/source?ref=…`)

Попадают сюда только из «Мои сообщения»; в чате ссылок нет.

- Шапка: «←» (на `/privacy`) + «Сообщение от 24 окт.».
- Текст сообщения — в пузыре `--bubble`, `pre-wrap` (не `<pre>`).
- Карточка «Разрешить публикацию»:
  - «Как» — сегментированный переключатель (radio-группа, стилизованная): «Дословно» → `identifiable_quotation`, «С указанием автора» → `identifiable_disclosure`. По умолчанию — «Дословно»;
  - «На срок» — «1 час» (1) / «Сутки» (24) / «Неделя» (168). По умолчанию — «Сутки»;
  - select «Аудитория» удалить; отправлять `audience: "public"` скрытым полем;
  - подсказка: «Агент сможет процитировать сообщение без имени.» / «Агент сможет упомянуть, что мысль ваша.» + «Публично, в Threads. Разрешение можно отозвать, но опубликованное не вернуть.»;
  - кнопка «Разрешить» → при успехе переход на `/privacy` и тост «Публикация разрешена до …».
- Карточка опасного действия: «Удалить сообщение» (цвет `--danger`), «Агент забудет всё, что из него узнал», кнопка «Удалить».
  - Нажатие открывает диалог (на мобильном — нижний лист): «Удалить сообщение?», «Сообщение и всё, что агент из него узнал, будут удалены здесь. У OpenAI, Cloudflare и Meta — по их правилам хранения.», кнопки «Отмена» / «Удалить» (красная).
  - Чекбокс «Подтверждаю локальное удаление» удалить: `confirm: "delete"` отправляется после подтверждения в диалоге.
  - При успехе — `/privacy` + тост «Сообщение удалено».

## 7. Панель владельца — `owner_control/static/*`

Палитра и переменные — как у чата (свой `owner.css` с теми же переменными, включая тёмную тему). Монограмма «AR» на фоне `--ink`.

- Заголовок страницы и `<title>` — «Almost Reasonable · Владелец». Удалить «Частный пилот» и «Управление приложением. Состояние воркера проверяется отдельно.»
- `#login-help` удалить, оставить только `<noscript>`.
- Шапка после входа: монограмма, «Владелец», «обновлено в 20:14», справа «Обновить» и «Выйти» (текстовые кнопки).
- Три плитки: **Приложение** (Работает / Stop), **Воркер** (Работает / Stop / Недоступен), **Расходы провайдера** (Идут / Приостановлены). Под значением — одна строка-пояснение (время последнего ответа, время сбора данных воркера, число попыток / без итога). Точка-индикатор: зелёная или `--danger`.
- **Аварийная остановка** — отдельный блок на фоне `--danger-soft`: заголовок, текст «Останавливает приложение и воркер. Уже отправленный провайдеру запрос и его стоимость не отменяются.», красная кнопка «Остановить всё» → диалог подтверждения. Если оба уже остановлены, блок скрыт, вместо него — жёлтая плашка «Stop воркера снимается только локально на его сервере.»
- **Stop только приложения** — строка с переключателем «Выкл / Вкл». Снятие (Вкл → Выкл) — через диалог «Снять Stop приложения?».
- Сворачиваемые блоки (`<details>`):
  - «Последняя активность» (открыт по умолчанию) — таблица: Время / Событие / Итог / Причина / Токены. Под таблицей — «Записанные токены — не данные биллинга.»;
  - «Диагностика» (закрыт) — пары ключ–значение: хранилище, реестр приватности, версия схемы, режим журнала, внешние ключи, ожидание блокировки, токены воркера, попытки с неполным учётом;
  - «Действия владельца» (закрыт) — время + действие.
- Удалить строки, которые никогда не меняются: «Биллинг провайдера — Не является источником данных этой панели», «Активация и разрешённый лимит — Недоступны этой панели…», «Фактическое использование провайдера — Не подтверждается этой панелью». Длинные оговорки из `#scope` и `#recent-activity > p` сократить до одной строки в соответствующем блоке.
- `confirm()` заменить на диалог.

## Что не трогать

- Маршруты, методы, коды ответов, CSRF/Origin-проверки, cookie, CSP, формат JSON API.
- Логику `sessionStorage`-восстановления и идемпотентной повторной отправки.
- Тексты `NOTICE_RU` и `NARRATIVE_DISCLOSURE_RU` в `app/privacy/notice.py`: в UI используются короткие формулировки, исходники остаются.

## Тесты

Тесты будут падать на старых строках (`Управление источником`, `Собеседник`, `Повторить отправку`, `Отменить повтор`, английские тексты ошибок, `#discard-pending`, `alert`). Обновить их под новые тексты и селекторы: `tests/test_private_web_browser.py`, `tests/test_private_web_http.py`, тесты owner control.

Добавить browser-проверки (Playwright, ширины 360 / 390 / 768 / 1280):
- нет горизонтального скролла на `/privacy`, `/privacy/source`, страницах ошибок, онбординге;
- на всех HTML-страницах есть `viewport` и `chat.css`;
- неверный пароль → остаётся на `/login` с текстом «Неверное имя или пароль»;
- после онбординга пользователь попадает на `/chat`;
- в DOM чата нет ссылок `/privacy/source`;
- тёмная тема: `emulateMedia({colorScheme:'dark'})` меняет `--bg`; выбор в меню сохраняется после перезагрузки;
- контраст текста ≥ 4.5:1 в обеих темах (axe-core или ручная проверка ключевых пар).
